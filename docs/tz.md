# Техническое задание (ТЗ) на разработку приложения QR-меню

Это техническое задание подготовлено на основе предоставленной блок-схемы (Mind map) и дополнительного файла **qr menu for claude.pdf**. Оно предназначено для дальнейшей разработки архитектуры и написания кода.

## 1. Архитектура пользовательского пути (User Flow)

### 1.1. Точка входа (Entry Point)
*   **Сканирование QR-кода:** Пользователь сканирует QR-код, размещенный на столе.
*   **Инициализация:** Приложение автоматически определяет ID ресторана и номер стола.
*   *Опционально:* Приветственный экран (Splash screen) или онбординг.

### 1.2. Каталог и Меню
*   **Главный экран меню:** Отображение категорий блюд (например, "Салаты", "Горячее", "Напитки").
*   **Навигация:** Скролл по категориям или выбор из верхнего/бокового меню.
*   **Карточка товара (Item Details):**
    *   Фотография блюда.
    *   Описание, состав, КБЖУ.
    *   Цена.
    *   Опции и модификаторы (например, "Без лука", "Степень прожарки", "Размер порции").
*   **Действие:** Кнопка "Добавить в корзину".

### 1.3. Корзина и Оформление заказа (Checkout)
*   **Экран корзины (Cart Screen):**
    *   Список добавленных позиций.
    *   Возможность изменить количество или удалить позицию.
    *   Подсчет итоговой суммы (Subtotal, налоги, сервисный сбор).
*   **Проверка авторизации (Decision: Is user logged in?):**
    *   *Да:* Переход к подтверждению заказа.
    *   *Нет:* Запрос номера телефона -> Ввод OTP (SMS-код) для идентификации.

### 1.4. Оплата (Payment)
*   **Выбор метода оплаты:**
    *   Оплата онлайн (Банковская карта, Apple/Google Pay).
    *   Оплата через официанта (Наличные или терминал).
*   **Процессинг (Payment Gateway):**
    *   *Успех (Success):* Перевод заказа в статус "Оплачен" / "Принят в работу".
    *   *Ошибка (Failure):* Уведомление об ошибке, предложение повторить оплату.

### 1.5. Отслеживание заказа (Order Status)
*   **Экран статуса:** Отображение текущего состояния заказа ("В очереди", "Готовится", "Готов", "Подан").
*   **Дополнительные действия:**
    *   "Дозаказать" (возврат в меню с сохранением стола).
    *   "Вызвать официанта".
    *   "Попросить счет" (если оплата не была произведена онлайн).

## 2. Разделы управления (Admin / Restaurant Side)

*   **Прием заказов:** Планшет или терминал у бармена/официанта для получения пуш-уведомлений о новых заказах.
*   **Управление статусами:** Перевод заказа из "Готовится" в "Готов".
*   **Управление столами:** Просмотр занятых столов и активных счетов.
*   **Редактирование меню (CMS):** Стоп-листы (если блюдо закончилось), изменение цен, добавление новых позиций.

## 3. Базовые технические требования
*   **Тип приложения:** Web App / PWA (не требует скачивания из App Store / Google Play).
*   **Адаптивность:** Mobile-first подход. Дизайн должен быть оптимизирован под экраны смартфонов.
*   **Скорость работы:** Быстрая загрузка изображений (использование CDN, lazy-loading).

## 4. Задачи для разработки (Промпт для дальнейших действий)
1.  Спроектировать архитектуру БД (Схемы таблиц: Users, Restaurants, Tables, Menu_Items, Orders, Order_Items).
2.  Подготовить API-документацию (REST или GraphQL) для связи фронтенда и бэкенда.
3.  Реализовать стейт-менеджмент для корзины на стороне фронтенда.
4.  Интегрировать мок-платежный шлюз для тестирования флоу оплаты.
